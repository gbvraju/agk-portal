# ADR-0025: Upgrade agk from 0.40.0 to 0.43.0

- Status: Proposed
- Date: 2026-10-23
- Deciders: maintainers
- Related: ADR-0020, ADR-0024
- Requirements: REQ-105

Protected classes: `scripts/agk/`, `agk.toml`

## Context

ADR-0020 took this install from 0.32.0 to 0.40.0. agk v0.43.0 (agk SPEC-0024) makes the `report.json` of the weekly product report schema 2: the item of kind `week-totals` gains `hours_unknown`, an integer always present. The report of Monday 2026-10-26 is schema 2. The portal's reader already accepts schemas 1 and 2 (ADR-0024); this repository's own `scripts/agk/product_report.py` is the source of the data its tests render (REQ-105 AC2 as worded), so it must be the kit's current copy.

## Decision

1. The install is upgraded from 0.40.0 to 0.43.0 by one run of the kit's `scripts/agk/upgrade.py` from a checkout of the tag v0.43.0, a dry run first and then for real. The run replaced exactly one file, `scripts/agk/product_report.py` (`REPORT_SCHEMA` 2 and `hours_unknown` on the totals), and set the `version` line of `agk.toml` to 0.43.0; every other vendored file was unchanged. The kit's workflows, the architect agents and the checks did not change between 0.40.0 and 0.43.0 in this install.
2. The upgrade is checked by `make governance` and `make test`, and by `agk doctor` run with `--kit-root` at the v0.43.0 checkout: 20 ok and 1 fail, the fail being `repo-auto-merge` (warn; the maintainers turn the setting on, ADR-0020). `kit-version`, `vendored-missing` and `vendored-differs` are all ok, so every vendored file equals the kit's copy byte for byte.
3. The tests that took the schema 1 report from the repository's script now take it from `writeReport` in `site/tests/support/report-script.ts`, which returns the script's report in its schema 1 form (the number 1 and no `hours_unknown`); the new `writeReportKit` returns the script's report as it is written (schema 2). A test shows that the script's schema 2 report equals the kit's v0.43.0 golden for the same facts (busy, kinds). No other test and no page code changes.
4. `scripts/agk/` and `agk.toml` are protected paths, so this change needs this ADR in the same pull request, naming each.

## Consequences

- `scripts/agk/product_report.py --json` writes schema 2 here, as the kit's workflow does from Monday 2026-10-26.
- The reader of ADR-0024 reads both schemas; nothing in the page changes.

## Residual

- 2026-10-23: the proof of an upgrade pull request reads `unknown (no-test-files)` when it changes no test file; here one test-support file changes, and the proof is the doctor's hash match plus the kit's own tested release (the kit residual recorded for ADR-0020 stands) (due 2026-12-31).
