# ADR-0027: Upgrade agk from 0.43.0 to 0.50.0

- Status: Accepted
- Date: 2026-10-24
- Deciders: maintainers
- Related: ADR-0020, ADR-0025, ADR-0026
- Requirements: REQ-105

Protected classes: `.claude/`, `.github/`, `agk.mk`, `scripts/agk/`, `agk.toml`

## Context

ADR-0025 took this install from 0.40.0 to 0.43.0. agk v0.50.0 (agk SPEC-0026) makes the `report.json` of the weekly product report schema 3, which the portal's reader accepts since ADR-0026 (merged in #52); this repository's own `scripts/agk/product_report.py` is the source of the data its tests render (REQ-105 AC2 as worded), and the report of Monday 2026-10-26 is made by the kit's workflow. The kit also adds three governance checks (numbers, final-clearance, pr-mode).

## Decision

1. The install is upgraded from 0.43.0 to 0.50.0 by one run of the kit's `scripts/agk/upgrade.py` from a checkout of the tag v0.50.0, a dry run first and then for real (`dry run: 11 files would change`, then `upgraded 11 files`). It replaced `.claude/agents/architect.md`, `.github/workflows/governance.yml`, `agk.mk`, `scripts/agk/common.py`, `scripts/agk/doctor.py`, `scripts/agk/facts.py`, `scripts/agk/metrics.py` and `scripts/agk/product_report.py`, created `scripts/agk/check_final_clearance.py`, `scripts/agk/check_numbers.py` and `scripts/agk/check_pr_mode.py`, and set the `version` line of `agk.toml` to 0.50.0. Every other vendored file was unchanged.
2. `pr_mode` stays `strict`: the kit's default is `strict`, and the upgrade only reported that the template of `agk.toml` has the key `pr_mode = "strict"`; `agk.toml` is the project's own file and no key was added. Changing the mode needs an ADR in the same pull request (`agk.toml` is a protected path).
3. The three new steps pass on this repository: `make governance` runs the numbers, final-clearance and pr-mode checks and exits 0. The pr-mode and final-clearance parts that need the pull-request files read nothing here and say `skipped`, as the kit's text says.
4. The upgrade is checked by `agk doctor --kit-root` at the v0.50.0 checkout (output in the pull request body): `kit-version`, `vendored-missing` and `vendored-differs` ok, so every vendored file equals the kit's copy byte for byte.
5. The tests that took data from the repository's script needed three test-only changes the upgrade forces, as ruled on #48: the schema 1 form of the script's report now also drops `counts`, `count` and `fix_verdicts_unknown`; the expected number of "Nothing this week" lines is one more for a quiet and an empty week, because the kit no longer lists a housekeeping total of 0 with no open issue (agk SPEC-0026 rule 6); and one test now shows the script's report equals the kit's v0.50.0 golden (busy, kinds). No page code changes.
6. `.claude/`, `.github/`, `agk.mk`, `scripts/agk/` and `agk.toml` are protected paths, so this change needs this ADR in the same pull request, naming each.

## Consequences

- `scripts/agk/product_report.py --json` writes schema 3 here, as the kit's workflow does from Monday 2026-10-26.
- The kit's governance gains the numbers, final-clearance and pr-mode steps.

## Residual

- 2026-10-24: the proof of an upgrade pull request that changes test-support files only reads on the hash match of the doctor and the kit's own tested release (the kit residual recorded for ADR-0020 stands) (due 2026-12-31).
