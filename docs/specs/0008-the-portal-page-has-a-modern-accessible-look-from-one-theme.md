# SPEC-0008: The portal page has a modern, accessible look from one theme

- Status: Draft
- Owner: maintainers
- Requirements: REQ-108

Status is `Draft` or `Approved`. An Approved spec is owned by its reviewer group; agents propose patches.
Written by the intake of one sentence, as data: "The portal page has a modern, accessible look from one theme of named colours that can be changed in one place, and works from a 360px phone to a wide screen without any script." The product owner gave 9 answers on 2026-10-23, before the files were written; they are the rules below, each with the test that proves it, and the intake decided nothing beyond them. The maintainers answered 3 questions before it was written; their answers, given at the review on 2026-10-23, are: the wording that SPEC-0005 rule 10 fixes (the status words, the page title, the removed card line) is changed by `docs/runs/proposed-spec-amendments-5.md`, applied by an ADR in the build pull request; the grouped At risk fold is not in this spec, because report.json carries no count for a grouped item and the length of `entries` would be a count the page computes, while the Needs your decision fold stays because its count is the data's own (`count`); and the four parts in two columns are Delivered, Proven, Needs your decision and At risk, with Time and review as full-width tiles. This spec changes how the page looks and which words it uses for status, for the title and for a fold; it does not change what the page computes (SPEC-0005 rule 9 and the report's data stay as they are) and it changes no security rule (SPEC-0004). Rules 4 and 8 touch wording that Approved specs fix (SPEC-0005 rule 10); they are applied to those specs only by `docs/runs/proposed-spec-amendments-5.md`, applied by an ADR in the build pull request (ruled by the maintainers, see above).

## Rules

1. **One theme, one place.** The page has one same-origin stylesheet (`/style.css`, served as now). Every colour in it is a custom property declared in one block: a light set under `:root` and a dark set under `@media (prefers-color-scheme: dark)`. No colour value (hex, `rgb`, `hsl`, a named colour) appears anywhere else in the stylesheet, which uses only `var(--name)`. No HTML element carries a `style` attribute: the HTML has classes only, so the Content-Security-Policy and the other headers stay exactly as SPEC-0004 fixes them and the staging header scan stays at A+. A test reads the stylesheet and fails on any colour value outside the block, and fails on any page that holds a `style` attribute; REQ-108 AC1.
2. **The tokens.** The theme names these tokens, light then dark: `bg` #F5F6F8 / #0E1116; `surface` #FFFFFF / #161A21; `surface-2` #F0F2F5 / #1D222B; `border` #E1E4EA / #2A303B; `text` #141820 / #E7EAF0; `muted` #566070 / #A0A9B7; `accent` #2B55C9 / #8EA9FF; `accent-ink` #FFFFFF / #0E1116; and for each status a background and a foreground: done #E3F3E9 and #1B6138 / #13301F and #8BD9AA; proven #E6ECFB and #22439E / #18234A and #AFC2FF; decide #FFF1DC and #7F4500 / #3A2710 and #FFC27A; risk #FCE8E5 and #9C271C / #3E1714 and #FF9E94; none #ECEEF1 and #4A5361 / #232833 and #B8C0CC. A test reads the token block and compares every value, in both sets, with this list; REQ-108 AC2.
3. **Contrast.** A test computes the WCAG 2 contrast ratio of every text and background pair of the theme in both sets: `text`, `muted` and `accent` on each of `bg`, `surface` and `surface-2` where the stylesheet uses them, `accent-ink` on `accent`, and each status foreground on its background. It fails for any pair below 4.5 to 1. (Computed by the intake on 2026-10-23 for the listed values: the lowest is `muted` on `surface-2` in the light set at 5.67; informational, the test decides.) REQ-108 AC3.
4. **Status is a word and a colour.** The status of an item is shown as a badge that always holds a word and a colour from the theme: Done (done), Proven (proven), Needs you (decide), At risk (risk), Not known yet (none). The colour never stands alone. A test fails on a badge element with no text, and on a status shown by colour or an icon only; REQ-108 AC4.
5. **Keyboard and touch.** The page uses only native controls: `a`, `button`, `input` and `details`/`summary`. Every one has a visible focus ring in the `accent` colour (a `:focus-visible` outline) and a target at least 44 px high. No `tabindex`, no `role` that replaces a native control and no script is used. A test checks the focus rule, the 44 px rule and the markup; REQ-108 AC5.
6. **Layout.** Mobile first: one column at 360 px, no horizontal scroll of the page (no element wider than its container; long words and addresses wrap), and a readable maximum width on a wide screen. The Time and review numbers (the per-change lines and the totals line, each a fixed phrase of SPEC-0005 rule 10) are shown as tiles. The other four parts (Delivered, Proven, Needs your decision, At risk) stand in two columns from about 900 px up and in one column below; their order in the markup stays the order of SPEC-0005 rule 2. No script is sent. A test checks the stylesheet's rules (the single column below the breakpoint, the two columns from it, the maximum width, the wrapping), that the markup holds the tiles and no script, and that no fixed width exceeds 360 px; REQ-108 AC6.
7. **Logo, fonts and icons.** The logo is the text "AGK" on the `accent` colour. The page loads no image file and no web font: the font is the system stack. An icon, where one is used, is inline SVG with `aria-hidden="true"` and is never the only carrier of meaning. A test fails on an `img` element, a `@font-face` or a font file, a request for any asset other than `/style.css`, and an SVG without `aria-hidden`; REQ-108 AC7.
8. **Content changes.** The page title of the signed-in page is "Your projects" (no new call to GitHub, no change to a security rule). The line "Facts read for {week}." is removed from a card that shows This week. A card without This week (no report, an unreadable report, an unknown repository) keeps the week: "Week {week}: not known yet: {reason}." where {reason} is the card's existing reason. A Needs your decision group with more than 5 items is folded in a `details` element whose `summary` is the group's existing heading with its count (no new phrase; the count is the data's own, `count`). A group of 5 items or fewer stays as SPEC-0005 rule 10 has it. The grouped At risk lines are not folded in this spec (ruled by the maintainers, see above and the Residual). A test checks each of these with the fixtures; REQ-108 AC8.
9. **Nothing else changes.** No script. Nothing is computed by the page: every sentence comes from `report.json` or is a fixed phrase and a number in a sentence is the data's own. The existing tests of SPEC-0005 still pass, except where rule 8 changes a phrase, and then the amended phrase replaces it in the same pull request. A test checks that the page holds no script and that a changed number in the data changes only the line that depends on it; REQ-108 AC8.

## Tests

- Rule 1: the colour values appear only in the token block of the stylesheet; no page holds a `style` attribute; the response headers equal SPEC-0004's; REQ-108 AC1.
- Rule 2: the token block equals the list, in both sets; REQ-108 AC2.
- Rule 3: the contrast of every pair is at least 4.5 to 1 in both sets, and a pair made lower fails the test; REQ-108 AC3.
- Rule 4: every badge holds a word of the five and its colour class, and a badge with no text fails; REQ-108 AC4.
- Rule 5: native controls only, the `:focus-visible` accent outline, the 44 px target and no `tabindex`; REQ-108 AC5.
- Rule 6: one column at 360 px, two columns from the breakpoint, the maximum width, wrapping, the tiles and no script; REQ-108 AC6.
- Rule 7: the logo text, no image and no web font, inline SVG with `aria-hidden`, no asset other than the stylesheet; REQ-108 AC7.
- Rules 8 and 9: the title, the removed line, the kept week, the Needs your decision fold over 5 and the unfolded 5 or fewer, no script and no computed sentence; REQ-108 AC8.

## Proof

REQ-108 AC1 and AC2: *the look is one theme in one place.* Rules 1 and 2. REQ-108 AC3 and AC4: *it is readable, and colour is never the only signal.* Rules 3 and 4. REQ-108 AC5: *it works from the keyboard and by touch.* Rule 5. REQ-108 AC6 and AC7: *it works from a 360 px phone to a wide screen with no script, no image and no web font.* Rules 6 and 7. REQ-108 AC8: *the words are the data's or fixed, and the page computes nothing.* Rules 8 and 9. The proof is a failing test on the base for each rule, the local proof reading proven, the screenshots of the page at 360 px and 1280 px in the light and the dark scheme attached to the build pull request, and the maintainers' check on staging after the merge.
